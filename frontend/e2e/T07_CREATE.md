# T-07 — E2E เพิ่มงานวิจัย (RED ก่อนสร้าง UI)

## วิธีทดลองและหลักฐานจริง

เปิด frontend ด้วย `node node_modules/vite/bin/vite.js --host=127.0.0.1 --port=5173 --strictPort` แล้วตรวจใน in-app browser ที่ `http://127.0.0.1:5173/` สำเร็จ (Vite ready) ก่อนบันทึกผลนี้ การเชื่อมต่อที่ล้มเหลวก่อนเปิด server ไม่นับเป็น RED

Actual R0: หน้าแสดงหัวข้อ “ระบบติดตามสถานะงานวิจัย” และข้อความ “อยู่ระหว่างเตรียมระบบใหม่” เท่านั้น ไม่มีปุ่มเพิ่มงานวิจัย, form, input, select, ปุ่มบันทึก/ยกเลิก/ย้อนกลับ หรือ dialog ใน accessibility tree

ทดลอง viewport 375×667 และ 1280×720 แล้วได้ R0 เหมือนกัน มี screenshot ในผล browser tool ของ task นี้ กด Tab บน desktop แล้วไม่พบ control สำหรับเพิ่มงานวิจัย จากนั้น reset viewport override แล้ว ไม่มีการส่ง POST หรือเลือกไฟล์จริง

ผล RED ของการเข้าสู่ flow ยืนยันจากหน้าเว็บที่เปิดได้จริง ส่วนกรณีปลายทางด้านล่างหยุดที่ prerequisite เดียวกัน จึงไม่อ้างว่าได้ทดลองส่งฟอร์ม/จำลอง API error/ตรวจ persistence แล้ว และยังไม่ถือว่า UI ผ่าน accessibility หรือ states ใด ต้องรันทุกกรณีหลังสร้าง UI ใน T-15

## Fixture และขั้นตอนร่วมสำหรับรอบ GREEN

- ใช้ฐานข้อมูลและ storage ทดลองแยกจากข้อมูลจริง เปิดทั้ง backend/frontend แล้วเริ่มด้วยรายการว่าง
- ข้อมูลปกติ: ชื่อ `Research ก`, ไม่เป็นทุนอุดหนุน, INTERNAL/Fund, สัญญา `CN-001`, RESEARCH/BUDGET, หน่วยงาน `Project unit`/`Budget unit`, 29/02/2567–01/03/2568, งบ 12345.67, บทคัดย่อไทย/อังกฤษ วัตถุประสงค์ คำสำคัญ มีค่าทั้งหมด
- หัวหน้า Lead / lead@example.com / University / 60%; ผู้ร่วม Co / co@example.com / Institute / 40%; PDF อ่านได้ 1 หน้า (ใช้ fixture จาก backend tests)
- เปลี่ยนเฉพาะค่าที่ case ระบุ; สร้างงานต้นทางจาก flow ปกติสำหรับ continuation บันทึก ID ไว้เฉพาะ test evidence/API ห้ามแสดงให้ผู้ใช้กรอก
- ทุก case เริ่มด้วยเข้าเว็บ → กดเพิ่มงานวิจัย → กรอก/เลือกข้อมูลตาม case ตรวจ network request, response และ test DB/files เมื่อต้องพิสูจน์ side effects
- ใช้ delay/network interception ใน test harness สำหรับ loading/API failure โดย response ต้องตรง OpenAPI และต้องทวน flow success/cancel กับ backend จริงก่อนปิด slice ห้ามสร้าง endpoint ทดลองใน production

## หลักการจาก frontend-design

ใช้ข้อความภาษาไทยที่ระบุการกระทำและแนวทางแก้ไขจริง เช่น บันทึกงานวิจัย/ยกเลิก/ย้อนกลับ แยก empty กับ error และคง focus/responsive/reduced motion ตาม SPEC การเลือกสีหรือสร้างหน้าตาจริงเป็นงาน implementation ไม่ได้ทำใน T-07 นี้

ตรวจโค้ด pages/components ต้องใช้ generated API client และไม่มี direct fetch; ไม่ใช้ build ผ่านแทน E2E ผ่าน ทั้งหมดข้างต้นเป็น acceptance checklist สำหรับรอบ GREEN ด้วย backend ทดลองจริง
